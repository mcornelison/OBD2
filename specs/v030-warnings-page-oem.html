Warnings page in the OEM skin

The real 480 × 320 Warnings page in the 90s Mitsubishi OEM style. Every active entry is in one list, ranked by the provider, and the list scrolls when it runs long. The warning icon in the top bar shows on every page. Two screens can cover the page. PULL OVER is for a live coolant red only, and it can't be dismissed. The code alert shows stored codes once per key-on: it can be dismissed, and it is never drawn while the car moves. Pick a scenario, then switch the page underneath, drive off, go stale, acknowledge, or let an acknowledge fail.

What the page reads

  • Only states/alerts. Each entries[] row is {id, source, key, tier, title, sentence, value, unit, firstSeenTs, active, stale, acknowledged}, already in the provider's order: tier, then live before stored, then newest. The page never sorts.
  • The icon renders icon.state, icon.count and icon.pulse exactly as given. A live STOP or WATCH outranks ?. MINOR-only shows as watch, which is counted and therefore amber (proposed to Atlas, G7).
  • The two screens come from takeover (coolant STOP, not dismissable) and codeAlert (ids[], dismissable). Titles and sentences are Spool's words, from the provider.
  • Acknowledge is POST /alerts-ack {id} and counts only for this boot. It is an honest write: the pulse stops, or the code alert closes, only when the re-read says so. On failure the screen stays, and says it couldn't save.
  • Only what was assessed. System and data checks aren't built in V0.30 (sources.system/data.assessed: false), so the empty state never claims they are clear.

Rules drawn here

  • Red is the STOP tier only, and today that means a live coolant red. A red RPM or battery tile is a WATCH entry with an amber icon. The tile shows where the value is; the tier says what to do.
  • PULL OVER reuses the shipped STOP skeleton: an opaque field, an 8 px red frame on the shipped stop-alarm-pulse, white copy, full brightness. It has no button. Tapping it stops the icon pulse only. It closes when the provider clears the entry, never because the data went stale.
  • The code alert uses the same skeleton with no pulse and no brightness override. Its frame takes the highest tier's chip colour. It has one real button, DISMISS, and is not drawn while moving (hiding it isn't a dismiss). PULL OVER outranks it.
  • REPLAY stays on top. The data-source marker sits above both screens.
  • Fit (measured, Michroma): PULL OVER 345.7 px at 44 · ENGINE OVERHEATING 416.1 px at 26 · TROUBLE CODES 315.5 px at 26 · DISMISS 123.0 px at 20 · NOT CHECKED 352.7 px at 34. The widest chip, UNRATED, is 107 px in a 116 px column.
