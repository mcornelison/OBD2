System page in the OEM skin

The real 480 × 320 System page in the 90s Mitsubishi OEM style, layout A: a verdict first, then one row each for the OBD link, data capture and sync, WiFi and the UPS. Brought up to the merged spec on 2026-10-22. Parked, a row opens its detail screen and the Pi line opens Pi health. SETTINGS and the ⋮ are always there; while not parked, Settings opens view-only. Everything is drawn from what a provider publishes; amber appears exactly on the verdict's members, and nowhere else.

Fixtures

What the page reads

  • Verdict: system-status.verdict {issueCount, members[{key, reason}]}. ALL OK, n ISSUE(S), or -- with no verdict (never ALL OK). The page counts nothing itself.
  • OBD: link.{bt, adapter, ecu}, each up / connecting / retrying / down / null with ts and lastOkTs, this session only. A member's reason is the sentence, verbatim; otherwise the first non-up layer speaks, from one lookup table.
  • DATA: the capture state from capture-health, then synced from sync.lastOkTs (today: time; yesterday; older: Oct 12; null: no sync on record). Rows: 12,345+ rows waiting when notCounted names tables, rows not read when null.
  • WIFI: wifi.state + home + source.wifi.reason. The emitter bands the RSSI; the page applies no threshold.
  • UPS: vcellV from battery-health, the sensed power.source (external or battery, never car or wall), and a freshness age (12 s ago, the M7 rule, not agoText).
  • Settings: the stored value via the overlay; a write shows saving…, then confirms from the re-read (saved) or snaps back (couldn't save). Never optimistic.

Rules drawn here

  • Amber means counted, and counted means amber. Every amber element carries the member it belongs to (data-m), and each fixture's amber set equals its member set (AC 7). Bluetooth trying to link, another network, weak WiFi, the UPS on battery and a stale sync are expected states: neutral, uncounted.
  • ARCH-061 closes: BT and ADAPTER green, ECU grey, ECU not answering (key off?), ALL OK. Parked key-off between attempts is n-n-n: Bluetooth trying to link (key off?), neutral. No word promises an outcome (takes ~1 min is gone).
  • Dashed = no reading; solid = a reading. A null layer is a dashed step and a hollow top-bar dot, never the down look.
  • WiFi glyph: up green; weak neutral; no reading (or associated with no level) dim arcs with no slash; down slashed (not associated is a reading, never a reason: Atlas A6); read_failed amber, the one counted WiFi state.
  • Locked until parked (gear P or N held 8 s, CIO 2026-10-22): Settings stays readable, every control goes tertiary with no −/+, a tap writes nothing, and one line says 🔒 view only — stop to change, or 🔒 view only — gear unknown while the gear is unknown. No word on the glass says moving.
  • Brightness FIXED runs from the effective minLevel (75 % shipped) to 100 % in 5 % steps; an unreadable minLevel disables FIXED and reads Unknown. AUTO→FIXED starts at the level the panel applies now.
  • Auto-dim ends step the 1-2-3-5 ladder from 1 to 1000 lux and cannot cross: the page disables the crossing step, and the seam's 400 is the rule.
  • No-data mark is --, never —. ⚠️ Shipped healthValue still returns — for an unknown health; the build owes the swap.
