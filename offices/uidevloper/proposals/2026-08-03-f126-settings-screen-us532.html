A Settings screen the operator can trust

Five config-backed controls — CIO chose to put them in the ⋮ System Setup menu (a Settings band above the existing service controls), not a separate card. Real values, honest saves

Every control reads the effective value from the state server (US-530), not a hardcoded default. A subtle set vs default marker shows whether it's an operator override or the shipped default.

On tap: saving… → confirmed from a re-read (saved), or on a rejected/failed write it snaps back to the real value + couldn't save — never an optimistic "on". The write is token-gated (US-531).

Apply-state per row

Power → live; Auto-analyze → next drive; Calibration → restart needed; Auto-rotate → RESTART, not live — the state server reads pi.display.carousel once at startup and serves it cached (Atlas verified this on the Pi), so "applies live" would have been a lie. A setting that isn't instant says so — a silent no-op that looks applied is the one thing this surface must never do.

Power mode = 3-state

CAR / WALL / UNKNOWN (not a toggle). Setting WALL fixes the bench "unknown" — the System-Status power tile then reads WALL.

One menu, two bands (B)

Settings on top, OBD-II Services + Exit below (kept confirm-gated, powerwatch-no-Stop). Opens via the ⋮ / long-press (parked-only). Scrolls. A divider + section labels keep "flip a preference" clearly distinct from "stop a service".
