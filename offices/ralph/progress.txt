- `SCHEMA_VERSION: int = 1` bare-int module constant (mirrors `power_watch.RECORD_SCHEMA_VERSION`),

- Pi startup wiring (import-and-splat): `database_schema.py` imports `EDR_SCHEMAS`/`EDR_INDEXES`
  from `common.edr.sensor_schema` and `*`-appends them into `ALL_SCHEMAS`/`ALL_INDEXES`, so the
  existing `ObdDatabase.initialize()` CREATE-IF-NOT-EXISTS loop creates the tables idempotently.
- Scope-fenced: NO `pi.sensors.*` config keys (owned by US-409/US-410); Pi-LOCAL ONLY, no server
  table created this phase (ADR section 2.5, F-115 adds server sync).

### Learnings for future iterations:
- **Pattern discovered**: To keep a `src/common/` DDL as the single source AND wire it into the Pi's
  existing table-creation loop, expose `*_SCHEMAS`/`*_INDEXES` `list[tuple[name, ddl]]` and
  `*`-splat them into `ALL_SCHEMAS`/`ALL_INDEXES`. The Pi inherits idempotency for free -- no
  bespoke create path, no second-boot risk.
- **Gotcha (import-root identity)**: `common.X` and `src.common.X` both resolve but are cached as
  DISTINCT module objects (dual import-root convention). A `foo is bar` identity check across the
  two roots ALWAYS fails; assert value equality (`==`) to prove "no divergent copy" instead.
- **Gotcha (index-in-ALL_INDEXES safety)**: a `drive_id` index is only safe in `ALL_INDEXES` when
  the column is defined in the table's own CREATE TABLE (true for the EDR tables). The US-200
  `realtime_data` drive_id indexes are deliberately NOT in `ALL_INDEXES` because that column was
  migration-added and may not exist when the indexer runs on a legacy DB.
- **Gotcha (env)**: mypy is not installed on this dev box; deferred to PM (module is fully hinted).

## 2026-06-30 - US-409 (Agent 1 / Rex / Session 51)
Task: EDR IMU + light readers -- additive bus topics + graceful-absence + presence STATE (ADR section 1/3)

### What was implemented:
- New Pi-tier package `src/pi/sensors/` with `sensor_reader.py`: the PRODUCER side of the
  EDR sensor path (US-410 = sibling persistence subscriber; US-411 = end-to-end harness).
- `ImuReader` + `LightReader` on ONE shared `_BaseSensorReader` scaffold (pmSignOff Rule-5
  batch-similar): the scaffold owns probe/graceful-absence, per-producer `seq`, retained
  presence STATE, and the daemon poll loop; the per-sensor read is the only delta.
- IMU = one BURST poll (accel+gyro+mag+temp read together) publishing
  `raw.imu.{accel,gyro,mag,temp}` all under the SAME `seq` -- read the whole burst BEFORE
  publishing so a mid-read fault emits nothing for that seq (atomic -> US-410 assembles one
  `edr_imu_sample` row per seq). Light = `raw.light.lux` (None on saturation/non-finite,
  never inf) + `raw.light.raw` counts under its own independent seq stream.
- Graceful-absence (the `pld_sensor` idiom): injectable `deviceFactory`; the real default
  lazy-imports `adafruit_icm20x`/`adafruit_tsl2591` and raises on a non-Pi host / absent bus.
  `probe()` catches -> `present=False`, logs once at WARN, publishes a RETAINED
  `state.sensor.*=absent` marker, starts NO poll thread -> pure silence, zero fabricated
  0.0/null. Present -> retained `state.sensor.*=present` + poll thread at `sampleHz`.
- Config: `pi.sensors.{imu,light}.enabled` (default False) each REQUIRE `pi.bus.enabled`
  (enforced in `createSensorReadersFromConfig`); `sampleHz` defaults 50/1. `persistHz` +
  `retentionDays` deliberately scope-fenced to US-410.
- One base-contract touch: widened `Sample.value` to `float | tuple[float, ...] | None` so a
  saturated `raw.light.lux` can publish None (annotation-only, back-compat).

### Files changed:
- Created: `src/pi/sensors/__init__.py`, `src/pi/sensors/sensor_reader.py`
- Modified: `src/pi/bus/sample.py` (Sample.value union widened to allow None)
- Modified: `src/common/config/validator.py` (4 pi.sensors.* DEFAULTS)
- Modified: `config.json` (mirrored pi.sensors section after pi.bus)
- Created: `tests/pi/sensors/__init__.py`, `tests/pi/sensors/test_sensor_reader.py` (15 tests)
- Modified: `tests/test_config_validator.py` (+2 sensor-defaults tests)

### Learnings for future iterations:
- **Pattern discovered**: on the SampleBus, "LOSSY / producer-never-blocks" is entirely a
  SUBSCRIBER-side property (drop-oldest lives in `Subscription._offer`). A producer just calls
  `bus.publish(sample)` and is non-blocking by construction -- a reader needs no QoS wiring.
- **Pattern discovered**: presence/STATE with a numeric-only `Sample.value` envelope -> encode
  present/absent as a float (1.0/0.0) and put the human label in `unit`; the shipped
  `test_bus_state.py` already encodes STATE as a float, so this is precedent, not a new idiom.
- **Gotcha (graceful-absence)**: mirror `pld_sensor` -- DI a `deviceFactory` whose default does
  the hardware import INSIDE the function (local import) so the module imports fine on a dev box
  with no sensor libs; constructing the device IS the I2C probe (WHO_AM_I read raises when absent).
- **Gotcha (ralph_agents.json)**: the `note` field had accumulated a stale concatenated tail from
  prior sessions; a prefix-only Edit compounded it into invalid JSON. Rewrite the whole small
  JSON file when the note churns, and `python -c "import json; json.load(...)"` to verify.
