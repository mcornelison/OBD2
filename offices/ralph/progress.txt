### Learnings for future iterations:
- **Pattern discovered**: THE DEADZONE MUST SURVIVE A VELOCITY MODEL. Adding
  velocity is adding a DIMENSION, not replacing distance. Drop the distance
  floor and a 5px twitch over 2ms reads as 2.5 px/ms -- four times the flick
  threshold -- so the carousel pages on a stray touch. Distance answers "was
  this a swipe at all?"; velocity answers "what KIND of swipe?". Two questions,
  two tests, both required. Pinned by test.
- **Gotcha**: DIVIDING BY A MEASUREMENT IS A FABRICATION RISK, and this one is
  FELT not just displayed. `travel/dtMs` with dt==0 is Infinity -> classified a
  flick -> auto-rotate RESUMES under the operator's finger. An unmeasurable
  duration is not an infinitely fast gesture; it contributes 0 and the travel
  test (a real reading) answers. Same for a 0-width card box on a transient 0x0
  layout pass. This project's honest-instrument rule is usually applied to
  RENDERED values -- it applies just as hard to DERIVED ones that drive behaviour.
- **Pattern discovered**: A CONFIG SCHEMA CAN MAKE A BAD STATE UNREACHABLE.
  `resolveCarouselConfig` accepts only finite POSITIVE numbers, so `resumeIdleS:
  0` falls back to the default and can never reach `shouldAutoResume` to disable
  the self-unpause. The "pause freezes the carousel forever" failure is not
  guarded against downstream -- it is inexpressible upstream. Prefer that to a
  defensive check at every consumer.
- **Gotcha**: FAIL A MISCONFIGURED INTERVAL TO **OFF**, NOT TO FAST. A
  non-positive `autoRotateS` naively means "advance when sinceMs >= 0" = every
  250ms tick. A carousel spinning at the poll rate is unusable and reads as a
  hardware fault. `shouldAutoAdvance`/`rotateProgress` both return false/0 on a
  non-positive period. Ask of any interval: what does 0 do?
- **Pattern discovered**: HANG A CROSS-CUTTING SIDE EFFECT ON ONE DOCUMENT-LEVEL
  LISTENER, NOT N CALL SITES. "Tap a card or open ANY overlay pauses" could have
  been 6+ per-overlay `pauseAutoRotate()` calls -- and overlay #7 forgets. One
  `document` `pointerdown` handler covers every present and future affordance,
  and the swipe handler resumes afterwards if it turns out to be a flick.
- **Gotcha**: A PROGRESS BAR MUST BE REMOVED WHEN IT STOPS, NOT FROZEN. Leaving
  the bar part-filled while paused is the exact frozen-instrument fabrication
  US-497 named for the g-dot: it promises an advance that is never coming. Same
  rule, different geometry.
- **Gotcha**: WHEN A STORY OVERTURNS A CONTRACT, THE OLD TEST IS EVIDENCE, NOT AN
  OBSTACLE. `test_nextVisibleIndex_clampsAtTheLastVisibleCard` went red BY DESIGN.
  I did not delete it -- I read what it was really guarding (never land on a
  hidden card), kept that assertion, and renamed it. Deleting it would have
  dropped a live invariant along with the dead one; flagged in completionNotes so
  the PM sees the contract change rather than a quietly-edited test.
- **Gotcha**: MEASURE THE TRAVEL FRACTION AGAINST THE REAL BOX. `#stage` is
  letterbox-scaled (US-482), so a hard-coded 480 misreads travel on any panel
  that is not 1:1. The handler reads `track.getBoundingClientRect().width`.
- **Verified, did not assume**: `main()` is the ONLY `StatesHttpServer`
  construction site, so the new config genuinely reaches the browser. That check
  is cheap and is exactly what US-494 (a dependency the entry point never
  injected) cost a whole story.

- **Gotcha**: A PIN THAT GREPS A DEFECT'S NAME FIRES ON ITS OWN DOCUMENTATION --
  SECOND OCCURRENCE. My renamed-renderer pin asserted `"renderLtftTrendCard" not
  in js` and went RED against CORRECT code, because the comment marking the
  deleted branch NAMES the function it replaced. Session 11 learned this exact

  comments, then grep.
- **Pattern discovered**: AND TEST THE STRIPPER, BECAUSE OVER-STRIPPING IS THE

  is string-aware and is itself pinned (code landmarks survive, the SVG namespace
  survives, real prose goes).
- **Gotcha**: A MERGE CAN MAKE AN OLD ASSERTION VACUOUS WITHOUT TURNING IT RED --
  the most dangerous test outcome there is. `assert "LTFT Trend" not in cards`
  guarded the vehicle gate; once no card carries that name it is true for the
  WRONG reason and would keep passing if the gate broke ENTIRELY. Replaced with a
  POSITIVE assertion (the section painted `data-gated="true"`). When a story
  removes the noun an absence assertion names, that assertion is dead -- re-aim it
  at the surface that now carries the property.
- **Pattern discovered**: MERGING CARDS MUST NOT MERGE THEIR FAILURES. The obvious
  implementation routes the merged card through the existing card-level
  availability check -- and then one dead UPS blanks the two live instruments
  beside it. That is a FABRICATED "nothing is readable" built out of one real
  fault. Resolve availability per SECTION.
- **Pattern discovered**: A GATE'S VOCABULARY IS A FUNCTION OF ITS CONTAINER. As a
  card, "does not apply" could be said by HIDING. As a section of an
  always-visible card, hiding leaves a hole, so the same fact must be said in
  WORDS. The disposition vocabulary grew from two to THREE (gated / no-data /
  live) -- and collapsing gated into no-data would tell an operator with a running
  engine that there is no engine.
- **Gotcha**: DELETE A DEAD BRANCH, DO NOT LEAVE IT UNREACHABLE. The `ltft-trend`
  tick branch still named the pre-rename `renderLtftTrendCard`. Nothing executed
  it, so nothing proved it still RESOLVED -- a ReferenceError armed for the day
  something re-declares that state. Same family as US-500 (the dangerous line is
  the one that never runs).
- **Verified, did not assume**: US-507's validationCriteria says "4 cards total",

- **Pattern discovered**: "ONLY SHOW WHAT IS BROKEN" HAS TWO OPPOSITE FAILURES,
  AND A FLOOR THAT FIXES ONE OPENS THE OTHER. Listing a green source is a
  fabricated fault; so is listing DRIVE=IDLE, which the card's own vocabulary
  documents as "nominal but inactive, NOT broken" -- that one would report a
  fault in the commonest state there is. But raise the floor to `amber` to be
  safe and the headline `SYSTEM · N UNAVAILABLE` becomes a tappable line that
  opens an EMPTY overlay: a new dead end, built while removing the old one. The
  floor is `unavailable`. Ask of any filter: what does the state JUST BELOW the
  cut look like when the summary above it is already counting that state?
- **Gotcha**: A COUNT IN THE HEADLINE AND A COUNT IN THE LIST ARE DIFFERENT
  FACTS. The summary counts ISSUES (amber/down); the list also carries
  known-unknowns, so the rows can outnumber N. Rather than force them equal (and
  lose a real fact) or let the overlay invent its own headline, the overlay head
  REPEATS THE TAPPED LINE VERBATIM -- two surfaces that must agree agree best
  when one of them is the other one.
- **Gotcha**: FRESHNESS IS A READING, SO IT CAN BE FABRICATED LIKE ANY OTHER.
  Only `obdLink` publishes `lastSeenS` (verified against the emitter, not
  assumed). The default "seen 0s ago" would claim we had just seen a source we
  never timed -- US-508's zeroed altitude in a different costume. Rows for
  ageless sources read "age not reported".
- **Gotcha**: AN OVERLAY OPENED FROM A SNAPSHOT GOES STALE WHILE YOU READ IT.
  Left as-opened, the drill-down prints "seen 42s ago" forever while the real age
  climbs -- the frozen-instrument fabrication already named for the g-dot
  (US-497) and the rotate bar (US-506), in a third geometry. It repaints on every
  poll, and when the last fault clears while it is open it SAYS "all sources OK"
  rather than showing an empty box or yanking itself shut under the operator.
- **Gotcha**: `-q` ON THE COMMAND LINE PLUS `-q` IN pyproject ADDOPTS = `-qq`,
  WHICH SUPPRESSES THE SUMMARY LINE ENTIRELY. I read dots-only output twice
  before noticing there was no "N passed" anywhere. The contract says to read the
  actual summary line; that is only possible if you have not silenced it.
- **Pattern discovered**: COMMIT THE GREEN WORK *BEFORE* MUTATION-PROVING. US-508
  solved "don't lose uncommitted work while mutating it" with in-`finally`
  backups; committing first is simpler and strictly safer -- restore becomes a
  plain `git checkout` and the diff-stat against HEAD proves the restore. 5
  mutations (strip the pause call / fabricate a zero age / lower the floor to
  neutral / always-tappable / fork a raw hex into the CSS) all went RED naming
  the right test.
- **Verified, did not assume**: `renderSystemStatusCard` lives in the shared
  render scope, NOT the deeper browser-only block where the DTC overlay's
  elements are captured. Defining the new overlay's helpers down there would have

## 2026-08-01 - US-511 (Agent 1 / Session 17)

### What was implemented:
- DEBOUNCE (AC-1): pure reducer `parkedInit()` / `parkedNext(prev, rawIdle,
  nowMs, cfg)` -> `{parked, raw, sinceMs}`. `parked` needs idle held TRUE for

  (3 s). Clock passed in, like every other US-506 predicate.
- SEAM (AC-2): `menuAccess(parked)` -- SIGNATURE CHANGED. It no longer takes the
  system-status payload and no longer calls `carouselIdle`, so keying the kebab
  off the raw flag is now inexpressible rather than merely discouraged.
- WIRING: `parkedSignal` lives in the enclosing browser scope;
  `updateMenuAccess(sysData, nowMs)` advances it from the SHARED tick clock.
- CONFIG (AC-4): `parkedOnS`/`parkedOffS` join `pi.display.carousel.*` and
  inherit `resolveCarouselConfig`'s positive-only rule. No new placeholder, no
  new loader -- `_loadDisplaySection` passes the section wholesale (verified).

### Files changed:
- Modified: `specs/UI/dist/dashboard-pi/carousel.js` (reducer + menuAccess + wiring)
- Modified: `config.json` (`pi.display.carousel.parkedOnS/parkedOffS`)
- Modified: `src/pi/splash/states_http_server.py` (docstring only -- no logic)
- Modified: `specs/architecture.md` (F-092 debounce subsection -- design-gate DoD)
- Created:  `tests/ui/test_carousel_parked_debounce.py` (30 tests)
- Modified: `tests/ui/test_carousel_menu_access.py` (7 pins re-aimed)

### Learnings for future iterations:
- **Pattern discovered**: A DEBOUNCE IS ONLY REAL IF THE CONSUMER CANNOT SEE
  PAST IT. `menuAccess` did its own ACQUISITION (it called `carouselIdle`
  internally), so adding a debouncer upstream would have left two live paths to
  the same fact and the next edit could take the raw one for free. Changing the
  signature to `menuAccess(parked)` is the actual fix; the reducer is just
  plumbing. Ask of any smoothing/validation layer: can the consumer still reach
  the unsmoothed value? If yes, you have added a convention, not a guarantee.
- **Gotcha**: NARROWING AN ARGUMENT FROM OBJECT TO BOOLEAN CREATES A FAIL-OPEN
  FOOTGUN. Every un-migrated caller keeps compiling and now passes a TRUTHY
  OBJECT. A `!!parked` test reads that as parked FOREVER -- the ⋮ pinned on
  screen at 70mph, the exact hazard the function exists to prevent. `parked ===
  true` makes the stale call shape fail CLOSED instead. When a parameter's type
  narrows, the old shape must land on the SAFE side, not merely be "wrong".
- **Pattern discovered**: HYSTERESIS IS RE-ANCHORING, NOT ACCUMULATING. The
  tempting implementation sums not-idle time; then six 2 s blips reach 3 s and
  un-park, so the flicker is not removed, only delayed and made harder to
  reproduce. Every CHANGE of reading must restart the run. Pinned by a
  six-blips-over-27 s sequence and mutation-proved by deleting the re-anchor.
- **Gotcha**: ASSERT ON EVERY INTERMEDIATE STATE, NOT THE FINAL ONE. A debounce
  that dips and recovers between two polls is exactly the defect under repair,
  and it lands in the same final state as one that never dipped. The test helper
  returns the state after EACH sample so `all(...)` can see the whole run.
- **Gotcha**: AN UNMEASURED HOLD MUST NOT BE HALF-RECORDED. My first cut stored
  the new reading when the clock was unreadable but left the old anchor -- so the
  next real clock credited THIS run's elapsed time to the PREVIOUS reading, a
  fabricated hold assembled from two halves. Return the state completely
  untouched; the next real sample re-anchors on the change for free. Found by
  tracing the test rather than by the test failing, which is the honest account.
- **Gotcha**: A NEGATIVE ELAPSED TIME STRANDS A SIGNAL SILENTLY. An NTP step
  back (this Pi has no RTC) makes `now - since` negative, and a run that can
  never reach its threshold again is frozen for the size of the step -- on the
  OFF edge that means the ⋮ stays up while the car drives away. Re-anchor on
  `held < 0`. Note the test must step the clock with the reading UNCHANGED: a
  step that coincides with a reading change re-anchors for the ordinary reason
  and would pass with no guard at all.
- **Gotcha**: THE PIN THAT GREPS A DEFECT'S NAME FIRED ON ITS OWN DOCUMENTATION
  AGAIN -- FOURTH OCCURRENCE (US-507, US-509), and this time the cause was the
  HELPER. `_fnBody` (copied from test_carousel_nav_model.py) slices "up to the
  next function declaration" at a FIXED 4-space indent, but carousel.js declares
  pure logic at 2-space and browser helpers at 4 -- so a 2-space function's
  "body" ran on all the way to the DOM block and swallowed the comment that
  documents the forbidden identifier. Fixed to cut at the function's OWN closing
  brace (indent-aware) and PINNED THE SLICER AT BOTH EDGES: over-stripping is
  the dangerous direction, because a slice cut to nothing makes an absence
  assertion pass VACUOUSLY. The loose helper still lives in the neighbouring
  suites -- routed to the PM, not fixed here (scope fence, no defect shown).
- **Gotcha**: THE MOST DANGEROUS BUG IN A DEBOUNCE IS WHERE ITS STATE LIVES.
  `var parkedSignal = parkedInit()` moved one line down (inside the per-tick
  function) leaves every pure test green while the kebab NEVER APPEARS -- a hold
  that resets every 250 ms cannot reach 8 s. No pure test can see this; it needs
  a source pin on the scope. Mutation-proved.
- **Verified, did not assume**: `_loadDisplaySection` passes `pi.display.<name>`
  through WHOLESALE with no key allow-list, so the two new tunables reach the
  browser with zero server change. Checked the loader rather than assuming the
  seam was generic -- the US-494 shape in reverse.

- LICENCE: `OFL.txt` into the kit AND vouched in `deploy-pi.sh`'s asset list.
- Re-aimed the US-510 pin that named BAHNSCHRIFT; kept its real invariant.

### Files changed:
- Modified: `specs/UI/tokens.css` (@font-face + stack + comment repair)
- Modified: `specs/UI/dist/dashboard-pi/dashboard.css` (mirror + weight tidy)
- Created:  `specs/UI/dist/dashboard-pi/OFL.txt` (SIL OFL 1.1, ships with kit)
- Modified: `deploy/deploy-pi.sh` (vouch OFL.txt so it is not pruned)
- Created:  `tests/ui/test_dashboard_brand_font_payload.py` (14 tests)
- Modified: `tests/ui/test_dashboard_fidelity_pass.py` (1 pin re-aimed)
- Modified: `specs/architecture.md` (BL-027-CLOSED under the two-file mirror)

### Learnings for future iterations:
- **Pattern discovered**: A MIRROR RULE APPLIES TO THE ASSET, NOT JUST THE
  VALUE. The dispatch said "add the @font-face to tokens.css" -- correct for a
  token, wrong for a FACE, because `dashboard.html` links only `dashboard.css`.
  An SSOT-only drop leaves the Pi on a fallback face while every token/mirror
  test stays green: the CIO's original "it looks generic" complaint, now with a
  passing suite on top of it. Same two-correct-halves shape as US-494/US-499.
  When a rule says "declared in both files", ask whether an @-rule is a
  declaration too. It is.
- **Gotcha**: A SINGLE-WEIGHT SUBSET IS A CONSTRAINT ON ITS CONSUMERS, AND CSS
  DOES NOT REFUSE. Asking 700 of a 600-only face does not fall back to the next
  family -- the browser SYNTHESISES a bold by smearing the 600, which on a
  condensed face reads as a rendering fault rather than a style. Nothing errors;
  it just looks broken. Pinned over the SET of bound rules so a future brand
  surface cannot reintroduce a 700 quietly.
- **Gotcha**: A SUBSET IS A CONTRACT WITH THE COPY, AND IT FAILS PER GLYPH.
  2,896 B buys A-Z/0-9/space/hyphen only. One `·` in a future card title does
  not fall back for the title -- it falls back for THAT GLYPH, splitting a word
  across two faces. So the subset assertion is paired with a pin that the
  wordmark is still the locked string: a glyph-coverage test that has stopped
  guarding the real copy is validating the drift's coverage instead.
- **Gotcha**: A LICENCE THAT IS NOT VOUCHED IS NOT SHIPPED. `refresh_asset_dir`
  PRUNES anything outside `deploy-pi.sh`'s asset list, so `OFL.txt` sitting in
  the kit directory would look compliant in the repo while `/opt/dashboard`
  shipped the embedded face bare. The font now travels INSIDE the stylesheet, so
  the licence has to travel with the stylesheet.
- **Gotcha**: A `;` INSIDE A CSS VALUE BREAKS THE OBVIOUS VALUE-GRABBER. A data
  URI contains one (`data:font/woff2;base64,`), so the `[^;]+` reader every
  other descriptor uses stops dead at `url(data:font/woff2` -- and then EVERY
  assertion about the src is made against a truncated string that happens to
  still look like a src. `src` got its own end-of-line reader.
- **Gotcha**: THE GREPS-A-DEFECT'S-NAME FAMILY, SIXTH OCCURRENCE -- this time in
  my own INSERTION SCRIPT, not a test. `assert '@font-face' not in text` tripped
  on the US-510 comment explaining that the @font-face was still owed. The fix
  is unchanged (strip comments first), but the lesson widened: any guard that
  greps for a name is exposed to the prose documenting that name, including
  one-off scripts.
- **Gotcha**: AN UNANCHORED GREP READS WHICHEVER DECLARATION COMES FIRST.
  `deploy-pi.sh` has TWO `local assets="..."` lists (splash + dashboard); my pin
  grabbed the splash one and reported its contents as the dashboard's. It
  failed loudly here only because the splash list lacks OFL.txt -- had it
  contained one, the pin would have passed VACUOUSLY. Anchor on the block's own
  landmark (`assetSrc=".../dashboard-pi"`), not on the first match in the file.
- **Verified, did not assume**: (a) the base64 decodes to `wOF2` magic and
  equals Iris's delivered binary byte-for-byte -- a font blob is the one artifact
  nobody can eyeball, so a truncated paste looks exactly like a working one;
  (b) the payload contains no `//` or `/*`, so no comment stripper can truncate
  it; (c) `parseCss` skips non-`@media` at-rules entirely, so the new block does
  not perturb any existing rule test.
