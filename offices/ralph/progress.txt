### Learnings for future iterations:
- **Pattern discovered**: To keep a `src/common/` DDL as the single source AND wire it into the Pi's
  existing table-creation loop, expose `*_SCHEMAS`/`*_INDEXES` `list[tuple[name, ddl]]` and

  bespoke create path, no second-boot risk.
- **Gotcha (import-root identity)**: `common.X` and `src.common.X` both resolve but are cached as

  two roots ALWAYS fails; assert value equality (`==`) to prove "no divergent copy" instead.
- **Gotcha (index-in-ALL_INDEXES safety)**: a `drive_id` index is only safe in `ALL_INDEXES` when
  the column is defined in the table's own CREATE TABLE (true for the EDR tables). The US-200
  `realtime_data` drive_id indexes are deliberately NOT in `ALL_INDEXES` because that column was
  migration-added and may not exist when the indexer runs on a legacy DB.
- **Gotcha (env)**: mypy is not installed on this dev box; deferred to PM (module is fully hinted).

## 2026-06-30 - US-409 (Agent 1 / Rex / Session 51)
Task: EDR IMU + light readers -- additive bus topics + graceful-absence + presence STATE (ADR section 1/3)

### What was implemented:
- New Pi-tier package `src/pi/sensors/` with `sensor_reader.py`: the PRODUCER side of the
  EDR sensor path (US-410 = sibling persistence subscriber; US-411 = end-to-end harness).
- `ImuReader` + `LightReader` on ONE shared `_BaseSensorReader` scaffold (pmSignOff Rule-5
  batch-similar): the scaffold owns probe/graceful-absence, per-producer `seq`, retained
  presence STATE, and the daemon poll loop; the per-sensor read is the only delta.
- IMU = one BURST poll (accel+gyro+mag+temp read together) publishing
  `raw.imu.{accel,gyro,mag,temp}` all under the SAME `seq` -- read the whole burst BEFORE
  publishing so a mid-read fault emits nothing for that seq (atomic -> US-410 assembles one
  `edr_imu_sample` row per seq). Light = `raw.light.lux` (None on saturation/non-finite,
  never inf) + `raw.light.raw` counts under its own independent seq stream.
- Graceful-absence (the `pld_sensor` idiom): injectable `deviceFactory`; the real default
  lazy-imports `adafruit_icm20x`/`adafruit_tsl2591` and raises on a non-Pi host / absent bus.
  `probe()` catches -> `present=False`, logs once at WARN, publishes a RETAINED
  `state.sensor.*=absent` marker, starts NO poll thread -> pure silence, zero fabricated
  0.0/null. Present -> retained `state.sensor.*=present` + poll thread at `sampleHz`.
- Config: `pi.sensors.{imu,light}.enabled` (default False) each REQUIRE `pi.bus.enabled`
  (enforced in `createSensorReadersFromConfig`); `sampleHz` defaults 50/1. `persistHz` +
  `retentionDays` deliberately scope-fenced to US-410.
- One base-contract touch: widened `Sample.value` to `float | tuple[float, ...] | None` so a
  saturated `raw.light.lux` can publish None (annotation-only, back-compat).

- Created: `src/pi/sensors/__init__.py`, `src/pi/sensors/sensor_reader.py`
- Modified: `src/pi/bus/sample.py` (Sample.value union widened to allow None)

- Modified: `tests/test_config_validator.py` (+2 sensor-defaults tests)

### Learnings for future iterations:
- **Pattern discovered**: on the SampleBus, "LOSSY / producer-never-blocks" is entirely a
  SUBSCRIBER-side property (drop-oldest lives in `Subscription._offer`). A producer just calls
  `bus.publish(sample)` and is non-blocking by construction -- a reader needs no QoS wiring.
- **Pattern discovered**: presence/STATE with a numeric-only `Sample.value` envelope -> encode
  present/absent as a float (1.0/0.0) and put the human label in `unit`; the shipped

## 2026-07-01 - US-410 (Agent 1 / Rex / Session 51)
Task: EDR persistence subscriber + rolling-window retention (ADR section 2.3/2.4/2.6)

### What was implemented:
- New `src/pi/bus/edr_persistence_subscriber.py` `EdrPersistenceSubscriber`: the CONSUMER
  side of the EDR sensor path (US-409 = producer readers; US-411 = end-to-end harness).
  A SIBLING of the OBD `PersistenceSubscriber` -- separate subscriber, separate LOSSY topics
  (`raw.imu.*`/`raw.light.*`, never `raw.obd.*`), separate tables (`edr_imu_sample`/
  `edr_light_sample`) -> the F-110 `realtime_data` byte-identical golden master is untouched
  BY CONSTRUCTION.
- BURST ASSEMBLY: accumulate fields per (table, seq); write exactly ONE `edr_imu_sample` row
  per seq -- flush on burst-complete (all 4 fields) OR the next-seq boundary (a dropped field
  persists NULL -- honest gap) OR the final flush on `stop()`. Light assembles lux+raw under
  its own seq.
- DECIMATION (ADR 2.3): whole-burst seq keep-1-of-N, N = round(imuSampleHz/imuPersistHz) =
  round(50/25) = 2 -> a 25 Hz decimated persist baseline (a SUBSCRIBER concern -- the bus still
  carries 50 Hz for a future live g-meter consumer). Light is not decimated (1 Hz).
- DRIVE_ID NULL-LATCH (ADR 2.4): stamp `getCurrentDriveId()` ONLY when the injected
  `isDrivingFn()` (wired in lifecycle to the live `DriveDetector.isDriving()` -- the SAME gate
  `event_router` uses for the KOEO read) reports a RUNNING drive, else EXPLICIT NULL. Default /
  uncertain / raising latch -> NULL. Never inherit a stale `_currentDriveId`.
- RETENTION (ADR 2.6): `purgeExpired()` DELETEs `ts_utc < cutoff` (lexicographic; utcIsoNow's
  fixed-width `%Y-%m-%dT%H:%M:%SZ` is compare-safe) from BOTH tables. `maybePurge()` runs the
  purge at most hourly on the SUBSCRIBER'S OWN drain thread -- NOT a new daemon, so no core.py
  runLoop edit (all EDR-persistence concerns stay in one SSOT module).
- Config: added `pi.sensors.imu.persistHz`=25 + `pi.sensors.retentionDays`=7 (US-409 already
  added enabled+sampleHz). Lifecycle `_startEdrSensorPath(bus)` builds+starts the readers +
  subscriber behind the flags (no-op with flags off); `_shutdownDataLogger` stops readers then
  the subscriber (flush) before the OBD subscriber.

### Files changed:
- Created: `src/pi/bus/edr_persistence_subscriber.py` (EdrPersistenceSubscriber + factory)
- Modified: `src/common/config/validator.py` (2 DEFAULTS: imu.persistHz, retentionDays)
- Modified: `config.json` (mirrored the 2 keys in pi.sensors)
- Modified: `src/pi/obdii/orchestrator/lifecycle.py` (_startEdrSensorPath wiring + shutdown)
- Created: `tests/pi/bus/test_edr_persistence_subscriber.py` (23 tests)
- Modified: `tests/test_config_validator.py` (+1 persistence-defaults test)

### Learnings for future iterations:
- **Pattern discovered**: burst assembly across an ordered single-producer stream -> buffer per
  (table, seq); flush on "all expected fields present" for the happy path AND on the next-seq
  boundary for the dropped-field path. Robust to LOSSY drops (partial -> NULL) without a timer.
- **Pattern discovered**: "piggyback on an existing maintenance tick, no new daemon" is best
  satisfied by the feature's OWN already-existing thread (the subscriber drain loop) with an
  interval-gated `maybePurge()` -- keeps the SSOT in one module and avoids editing core.py's
  runLoop (lower base-module blast radius than adding a `_maybeTrigger*` there).
- **Gotcha (drive_id latch)**: the ADR says stamp `getCurrentDriveId()` gated on RUNNING -- so
  the subscriber IGNORES `sample.driveId` and re-resolves via an injected isDrivingFn at persist
  time (mirroring the DTC-KOEO ruling). The safe default (no fn) is always-False -> NULL, so an
  unwired latch never fabricates a drive attribution.
