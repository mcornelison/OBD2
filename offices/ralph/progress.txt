## 2026-08-01 - US-501 (Agent 1 / Rex)
Task: Wire the dashboard version chip to .deploy-version (stop showing 'V?.?.?')

### What was implemented:
- dashboard.html header chip now carries a `__DEPLOY_VERSION__` placeholder
  instead of the hard literal `V?.?.?` that never changed on a deploy.
- states_http_server `_injectHtml` substitutes it at serve time, on the SAME
  seam as `__SPLASH_TOKEN__` / `__DISPLAY_AUTODIM__` / `__DISPLAY_CAROUSEL__`.
  No JS reader was added -- one rule owns the chip.
- The version is read PER REQUEST, not closed over at handler construction.
- New fail-safe reader `readDeployVersion()`: returns None (never a guess) for
  no-path / absent / unreadable / malformed-JSON / missing / blank / non-string
  version. The chip then renders the same `V?.?.?` sentinel the splash uses.
- CLI `--deploy-version-path` defaults to `.deploy-version`, WorkingDirectory-
  relative -- so the unit file and deploy script needed NO change.

### Files changed:
- Modified: `specs/UI/dist/dashboard-pi/dashboard.html` (chip -> placeholder)
- Modified: `src/pi/splash/states_http_server.py` (placeholder + sentinel
  constants, per-request substitution, readDeployVersion, CLI arg)
- Created: `tests/pi/splash/test_states_http_deploy_version.py` (14 tests)
- Created: `tests/ui/test_dashboard_version_chip.py` (4 tests, incl. the real
  kit served by the real server)

### Learnings for future iterations:
- **Gotcha (load-bearing)**: deploy-pi.sh writes `.deploy-version` LAST
  (step_write_deploy_version, line 1955) but restarts eclipse-states-http
  EARLIER (step_install_state_server_units, line 1939) -- deliberately, per
  US-354, so a failed restart can't bump the stamp on a Pi running old code.
  ANY value a long-running Pi service caches from `.deploy-version` at startup
  is therefore one deploy STALE, permanently. Read it per use. This is invisible
  to a unit test that only ever reads once; the guard is a test that rewrites
  the file mid-server-life. Mutation-proved: caching makes the chip render
  V0.29.23 after V0.29.24 was stamped.
- **Pattern discovered**: the `_injectHtml` placeholder seam has TWO flavours.
  The config ones are QUOTED (`"__X__"`) so an un-substituted file:// preview
  stays valid JS. That trick does NOT apply to HTML *text content* -- an
  unsubstituted preview shows the raw `__DEPLOY_VERSION__`. Accepted as
  unmistakably "not substituted" and dev-only, but flag it to Iris rather than
  inventing a third mechanism.
- **Gotcha**: a "no dead literal in the markup" guard that greps raw file text
  will trip on your own explanatory HTML comment discussing that literal. Strip
  comments and assert only on renderable markup.

## 2026-08-01 - US-502 (Agent 1 / Rex)
Task: Wire the real power source to the System-Status power tile + header bolt

### What was implemented:
- `CardStateEmitterMixin._gatherPowerSource` (new) reads the
  `PowerSourceProvider` SSOT (X1209 GPIO6 PLD) directly. The tile previously
  read `PowerMonitor.readPowerStatus()`, whose reader is never configured in
  the orchestrator -> `source` was permanently "unknown" -> tile rendered its
  "unavailable" branch + header bolt gray, while the real fact was already
  reaching `power_log` through the B1 `_PowerSourceUiBridge`.
- `PowerMonitor` is REMOVED from that path. A second acquisition path could
  disagree with GPIO6 -- the SSOT violation the design gate forbids.
- New `PowerSourceProvider.isAvailable` property (the ONLY contract change):
  exposes whether the line is readable, so each consumer applies its own
  uncertainty policy over the one fact. `isExternalPowerPresent` /
  `isPowerLost` / `startupArmCheck` untouched -- shutdown path did not move.
- The provider is read LAZILY, per emit, via `getattr`.
- `specs/architecture.md` §2 gained "UI consumer wired (US-502)" (design gate).
- A2AL seam-confirm note filed to Atlas for the `isAvailable` delta.

### Files changed:
- Modified: `src/pi/obdii/orchestrator/card_state_emitter.py` (tile source
  re-pointed to the SSOT; PowerMonitor dropped from the path)
- Modified: `src/pi/power/power_source_provider.py` (`isAvailable` property)
- Modified: `specs/architecture.md` (§2 UI-consumer subsection)
- Modified: `tests/pi/orchestrator/test_card_state_emitters.py` (fakes moved
  from the dead PowerMonitor reader to the provider)
- Modified: `tests/pi/power/test_power_source_provider.py` (+2 readability)
- Created: `tests/pi/orchestrator/test_card_power_source_wiring.py` (10 tests)
- Created: `tests/ui/test_carousel_power_source_wiring.py` (3 chain tests)
- Created: `offices/architect/inbox/2026-08-01-from-ralph-us502-power-source-ui-seam.md`

### Learnings for future iterations:
- **Pattern discovered (the load-bearing one)**: when ONE fact has two
  consumers with different consequences of being wrong, the SSOT exposes the
  FACT and each consumer keeps its OWN uncertainty policy. Here the
  ShutdownSequencer's safe direction is "unreadable => treat as power
  present" (never self-brick on a dead signal) -- but reusing that on a
  display paints a confident lit "external" off a DEAD GPIO, which is
  strictly worse than the gray bolt the story exists to fix. Resist the
  tempting shortcut of a display-shaped tri-state return: that puts policy
  INSIDE the SSOT. Add the fact, keep the policies at the edges.
- **Gotcha (2nd sighting this sprint, same shape as US-501's stale
  `.deploy-version` cache)**: BOOT ORDER. The card emitters are constructed
  in `_initializeAllComponents`, but `_powerSourceProvider` is not built
  until `_startHardwareManager`, which `runLoop` calls LATER. A provider
  reference captured at emitter-init time is `None` for the entire life of
  the process = permanently dead tile with fully green unit tests. Read
  late-bound dependencies AT USE TIME, and pin it with a test that attaches
  the dependency AFTER init. Check the construction site's position in the
  boot order before caching anything in this codebase.
- **Gotcha**: two halves that are each individually correct can simply never
  have been connected. `carousel.js` always rendered `battery`/`external`
  correctly and the Pi always knew the real state -- nothing carried it
  across, and a test on either half alone stays green through that. The
  catch requires feeding the REAL emitted state file into the REAL renderer
  (node). Same lesson as US-494/US-499.
- **Gotcha (test fidelity)**: the fake PLD must reproduce the real
  `PldSensor` contract that an UNREADABLE line returns
  `isExternalPowerPresent() == True` (the safe direction), not the stored
  value. A fake returning the stored value hides the exact lie the story is
  about.

## 2026-08-01 - US-503 (Agent 1 / Rex)
Task: Idle-card clock to 12-hour AM/PM

### What was implemented:
- `fmtClock` renders a 12-hour AM/PM face: mod-12 with the 12 restored for
  midnight/noon, a BARE hour (`2:05 PM`, never `02:05 PM`), a zero-padded
  minute, no seconds. Purely a format change -- no data source, no state
  file, no emitter touched; the Date is still supplied by the caller.
- `fmtClock` + its `two()` padding helper MOVED from the browser-only block
  up into the pure/exported section, and `fmtClock` is now on `api`.
  carousel.js holds exactly ONE clock formatter; the DOM block calls it.
- New `tests/ui/idle_clock_probe.js` -- a deterministic node probe that
  builds a local Date from calendar components and prints `fmtClock`.

### Files changed:
- Modified: `specs/UI/dist/dashboard-pi/carousel.js` (12-hour formatter,
  relocated to the pure section + exported; DOM-block comment updated)
- Created: `tests/ui/test_carousel_idle_clock.py` (10 tests -- 9 formatter
  cases + 1 end-to-end read of the rendered `.idle-clock` element)
- Created: `tests/ui/idle_clock_probe.js` (deterministic clock probe)

### Learnings for future iterations:
- **Gotcha (why the move was forced, not chosen)**: carousel.js runs under
  `"use strict"`, where an ES6 function declaration inside a block is
  BLOCK-SCOPED. Anything declared inside
  `if (typeof document !== "undefined") { ... }` is therefore invisible to
  the `api` export literal -- hoisting does NOT rescue it. So "just add it
  to `api`" is not an option for a helper in that block; it has to
  physically move. Check which side of that brace a function lives on
  before planning to test it.
- **Pattern discovered**: that block's header comment ("the pure view logic
  stays clock-free (deterministic tests), so these live in the DOM layer")
  was true of `fmtDate` but never of `fmtClock` -- `fmtClock` only ever
  formatted the Date it was HANDED, so it was pure all along and the
  comment was quietly protecting the wrong function. A rationale written
  for a group is worth re-checking per member before inheriting it.
- **Gotcha (3rd sighting this sprint of the two-correct-halves shape)**:
  mutation-testing proved the end-to-end test is the one that matters here.
  Re-declaring the OLD 24-hour `fmtClock` inside the DOM block leaves ALL
  NINE formatter unit tests green -- they exercise the exported one -- and
  is caught ONLY by the test that boots the shipped carousel.js over the
  shipped markup and reads the rendered `.idle-clock` text. Same lesson as
  US-494/US-499/US-502: when a fix RELOCATES a function, something must pin
  that the caller moved with it.
- **Pattern discovered**: `carousel_probe.js` JSON-decodes its argv, and
  JSON has no Date -- passing an epoch hands the function a Number and it
  reads NaN. For any Date-taking export, write a small dedicated probe that
  builds the Date from local calendar COMPONENTS: the fixture is then the
  clock FACE, not an instant, and the assertions hold in any timezone.
- **Gotcha (deferred, for the on-Pi drill)**: `.idle-header` is a flex row
  (wordmark + clock + date, gap 8px) on the 480px design stage and the
  clock string grew ~3 glyphs. `render_harness.py` resolves CSS but does NO
  text metrics, so crowding is undetectable from here -- do not pre-tighten
  the stylesheet on a guess; flag it for the panel read.
