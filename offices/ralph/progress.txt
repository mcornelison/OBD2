### Learnings for future iterations:
- **Pattern discovered**: SUBSUME-not-mint identity migration -- inserting the old PK value as the new autoincrement PK (`INSERT ... SELECT ds.id`) preserves existing FKs numerically, so the FK *constraint* re-point (US-451) is a schema-only change with zero data movement.
- **Pattern discovered**: tripwire OUTPUT re-point -- keep the detector grouping on the RAW signal (never regroup by the deduped server id, which blinds the backstop); add a separate resolver that maps the detected raw ids to canonical identity for the flag/output only.
- **Gotcha**: `test_db_models.py::test_totalTableCount` was already stale (expected 25, actual 26 -- US-436's drive_derived_signals was never added to it). Any new table forces this lockstep update; correct the true count, don't just +1.
- **Gotcha**: bench-only sprint -- 'deployed AND verified via INFORMATION_SCHEMA' is a PM/deploy gate (no MariaDB on Windows dev); migrations are validated via hermetic FakeRunner (DDL/subsume/ordering/post-probe) + SQLite ORM, never a live server.
