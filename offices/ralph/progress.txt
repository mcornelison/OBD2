### Learnings for future iterations:
- **Pattern discovered**: THE DEADZONE MUST SURVIVE A VELOCITY MODEL. Adding
  velocity is adding a DIMENSION, not replacing distance. Drop the distance
  floor and a 5px twitch over 2ms reads as 2.5 px/ms -- four times the flick
  threshold -- so the carousel pages on a stray touch. Distance answers "was
  this a swipe at all?"; velocity answers "what KIND of swipe?". Two questions,
  two tests, both required. Pinned by test.
- **Gotcha**: DIVIDING BY A MEASUREMENT IS A FABRICATION RISK, and this one is
  FELT not just displayed. `travel/dtMs` with dt==0 is Infinity -> classified a
  flick -> auto-rotate RESUMES under the operator's finger. An unmeasurable
  duration is not an infinitely fast gesture; it contributes 0 and the travel
  test (a real reading) answers. Same for a 0-width card box on a transient 0x0
  layout pass. This project's honest-instrument rule is usually applied to
  RENDERED values -- it applies just as hard to DERIVED ones that drive behaviour.
- **Pattern discovered**: A CONFIG SCHEMA CAN MAKE A BAD STATE UNREACHABLE.
  `resolveCarouselConfig` accepts only finite POSITIVE numbers, so `resumeIdleS:
  0` falls back to the default and can never reach `shouldAutoResume` to disable
  the self-unpause. The "pause freezes the carousel forever" failure is not
  guarded against downstream -- it is inexpressible upstream. Prefer that to a
  defensive check at every consumer.
- **Gotcha**: FAIL A MISCONFIGURED INTERVAL TO **OFF**, NOT TO FAST. A
  non-positive `autoRotateS` naively means "advance when sinceMs >= 0" = every
  250ms tick. A carousel spinning at the poll rate is unusable and reads as a
  hardware fault. `shouldAutoAdvance`/`rotateProgress` both return false/0 on a
  non-positive period. Ask of any interval: what does 0 do?
- **Pattern discovered**: HANG A CROSS-CUTTING SIDE EFFECT ON ONE DOCUMENT-LEVEL
  LISTENER, NOT N CALL SITES. "Tap a card or open ANY overlay pauses" could have
  been 6+ per-overlay `pauseAutoRotate()` calls -- and overlay #7 forgets. One
  `document` `pointerdown` handler covers every present and future affordance,
  and the swipe handler resumes afterwards if it turns out to be a flick.
- **Gotcha**: A PROGRESS BAR MUST BE REMOVED WHEN IT STOPS, NOT FROZEN. Leaving
  the bar part-filled while paused is the exact frozen-instrument fabrication
  US-497 named for the g-dot: it promises an advance that is never coming. Same
  rule, different geometry.
- **Gotcha**: WHEN A STORY OVERTURNS A CONTRACT, THE OLD TEST IS EVIDENCE, NOT AN
  OBSTACLE. `test_nextVisibleIndex_clampsAtTheLastVisibleCard` went red BY DESIGN.
  I did not delete it -- I read what it was really guarding (never land on a
  hidden card), kept that assertion, and renamed it. Deleting it would have
  dropped a live invariant along with the dead one; flagged in completionNotes so
  the PM sees the contract change rather than a quietly-edited test.
- **Gotcha**: MEASURE THE TRAVEL FRACTION AGAINST THE REAL BOX. `#stage` is
  letterbox-scaled (US-482), so a hard-coded 480 misreads travel on any panel
  that is not 1:1. The handler reads `track.getBoundingClientRect().width`.
- **Verified, did not assume**: `main()` is the ONLY `StatesHttpServer`
  construction site, so the new config genuinely reaches the browser. That check
  is cheap and is exactly what US-494 (a dependency the entry point never
  injected) cost a whole story.

### Learnings for future iterations:
- **Gotcha**: A PIN THAT GREPS A DEFECT'S NAME FIRES ON ITS OWN DOCUMENTATION --
  SECOND OCCURRENCE. My renamed-renderer pin asserted `"renderLtftTrendCard" not
  in js` and went RED against CORRECT code, because the comment marking the
  deleted branch NAMES the function it replaced. Session 11 learned this exact
  shape on `NoInputNoOutput`/`PYEOF`. It recurs because the fix (document the
  rename) and the test (forbid the old name) pull in opposite directions. Strip
  comments, then grep.
- **Pattern discovered**: AND TEST THE STRIPPER, BECAUSE OVER-STRIPPING IS THE
  DANGEROUS DIRECTION FOR AN ABSENCE ASSERTION. A stripper that eats too much
  removes the very text the test hunts for, so the pin passes VACUOUSLY. Concrete
  hazard here: carousel.js:2331 is `"http://www.w3.org/2000/svg"` -- a STRING
  containing `//`, which a naive line-comment strip truncates. `_stripJsComments`
  is string-aware and is itself pinned (code landmarks survive, the SVG namespace
  survives, real prose goes).
- **Gotcha**: A MERGE CAN MAKE AN OLD ASSERTION VACUOUS WITHOUT TURNING IT RED --
  the most dangerous test outcome there is. `assert "LTFT Trend" not in cards`
  guarded the vehicle gate; once no card carries that name it is true for the
  WRONG reason and would keep passing if the gate broke ENTIRELY. Replaced with a
  POSITIVE assertion (the section painted `data-gated="true"`). When a story
  removes the noun an absence assertion names, that assertion is dead -- re-aim it
  at the surface that now carries the property.
- **Pattern discovered**: MERGING CARDS MUST NOT MERGE THEIR FAILURES. The obvious
  implementation routes the merged card through the existing card-level
  availability check -- and then one dead UPS blanks the two live instruments
  beside it. That is a FABRICATED "nothing is readable" built out of one real
  fault. Resolve availability per SECTION.
- **Pattern discovered**: A GATE'S VOCABULARY IS A FUNCTION OF ITS CONTAINER. As a
  card, "does not apply" could be said by HIDING. As a section of an
  always-visible card, hiding leaves a hole, so the same fact must be said in
  WORDS. The disposition vocabulary grew from two to THREE (gated / no-data /
  live) -- and collapsing gated into no-data would tell an operator with a running
  engine that there is no engine.
- **Gotcha**: DELETE A DEAD BRANCH, DO NOT LEAVE IT UNREACHABLE. The `ltft-trend`
  tick branch still named the pre-rename `renderLtftTrendCard`. Nothing executed
  it, so nothing proved it still RESOLVED -- a ReferenceError armed for the day
  something re-declares that state. Same family as US-500 (the dangerous line is
  the one that never runs).
- **Verified, did not assume**: US-507's validationCriteria says "4 cards total",
  but this story ALONE lands at 5 -- absorbing the Motion card into the home slot
  is US-508's acceptance, not US-507's. I did NOT delete it (scope fence + it would
  open a regression window between the two stories) and routed the criteria
  correction to the PM instead of quietly meeting or quietly missing the number.
