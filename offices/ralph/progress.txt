### Learnings for future iterations:
- **Pattern discovered**: when N consumers must agree on ONE fact, assert the
  AGREEMENT, not each consumer separately. Dropping the seam from one reader left
  the other reader's own test green -- a per-reader suite ships the divergence.
  And pick a fixture value that DIFFERS from the default: my parity test is
  parametrized [0, 8, 20] because 8 IS the shipped default, so a parity test
  using only 8 passes against a completely broken reader.
- **Gotcha**: deploy-pi.sh has TWO sync paths, and the tar fallback WIPES the
  remote tree before extracting. Excluding a file from the tarball is NOT the
  same guarantee as surviving the delete -- the preserve `find` needed its own
  `! -name` entry or every rsync-less deploy would silently erase operator
  settings. Re-prove a durability guarantee in the fallback path, not just the
  primary one.
- **Gotcha**: a log line is a DECLARATION, not a mechanism. With the power-mode
  coercion removed, the WARNING still read "resolving to unknown" while the code
  no longer did. Only the assertion pins the behaviour.
- **Gotcha**: `bash -n` any .sh you touch -- pytest cannot see a shell syntax
  error. `make` is not on PATH here (exits 127, which reads like a pass).
