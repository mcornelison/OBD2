- **Pattern discovered**: when two acceptance clauses genuinely conflict, pick by WHICH

- **Gotcha**: `ruleBlock()` must be line-anchored. A substring search for

- **Gotcha**: a COMMENT containing the literal `@import` fails two offline-kiosk font
  guards that scan raw file text. Reword the comment; never weaken the guard.
- **Gotcha**: the Bash tool is bash -- PowerShell here-strings (`@'...'@`) leak a literal
  `@` into the commit subject. Use a real heredoc or `git commit -F <file>`. `/tmp` and
  `.git/` are both blocked for writes; stage scratch files inside the repo.

### Learnings for future iterations:
- **Gotcha (cost the previous iteration its commit)**: A SCOPED GATE IS ONLY A
  GATE OVER WHAT IT COLLECTS. A prior iteration reached green on `tests/ui` and
  died before committing -- while `tests/deploy/test_dashboard_kit.py` was
  already RED on that same tree, pinning the 4-card count and the `data-states`
  binding. `tests/ui` is the wrong fence for a change to the SHIPPED MARKUP.
  When touching `specs/UI/dist/**`, run tests/ui AND tests/deploy/test_dashboard_kit.py,
  and `git grep -l '<the markup token you changed>' -- tests/` before trusting green.
- **Pattern discovered**: an orphan-check written against ONE layer does not
  cover the other. This story's own `TestNoOrphanedHealthCode` was built to catch
  ghosts and caught the JS half, while a dead `data-vehicle-speaks` attribute sat
  in the markup unread. Assert absence on BOTH sides of a markup/renderer pair.
- **Pattern discovered**: prove count-agnosticism by BOOTING a different count,
  never by grepping for the old literal -- a hard-coded 4 could live in the CSS,
  the dot loop or the translate math. Paired with pinning `clampIndex` (CLAMPS)
  and `nextVisibleIndex` (WRAPS) separately: asserting one contract for both
  hides a real break in whichever helper is not being described.
- **Gotcha**: an inventory assertion must be an ORDERED list once order is part
  of the deliverable. The deploy-kit docstring already warned a bare count was
  vacuous; a set-or-count assertion still goes green on a carousel opening on Light.
- **Gotcha**: the Bash tool refuses a `for f in ...` loop outright ("contains
  simple_expansion"). `pytest -q` prints no summary line on this tree -- redirect,
  then `echo $?` AND `grep -cE '^(FAILED|ERROR)'`; for a total, sum the
  `--collect-only -q` per-file counts with awk.
