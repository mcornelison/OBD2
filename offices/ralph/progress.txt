### Outcome: VERIFY-FIRST root-cause COMPLETE from code; BLOCKED for live-Pi fix disambiguation. No src/tests changed (deliberate).

### Root cause (code-verified -- the shipped escalation is fine, the miss is downstream):
- The US-242/B-049 alternator-active escalation FIRES correctly (BATTERY_V > 13.8V
  sustained 3 samples -> _injectRpmProbeForEscalation). The RESIDUAL miss is what
  happens to the probe (and every regular RPM poll):
  1. supported_commands is probed ONCE at connect (obd_connection.py:408), never refreshed.
  2. Cold-boot connect while the ECU is DARK (car key OFF, ELM327 alive on pin-16)
     omits RPM(0x0c) from python-obd's supported_commands.
  3. RPM's query is the LEGACY path (RPM in LEGACY_ECU_PARAMETERS, NOT PARAMETER_DECODERS)
     -> obd.query(cmd) with force=False returns NULL without wire traffic for an
     unsupported cmd (logger.py:220) -> ParameterReadError.
  4. _assertPidSupported is a RED HERRING for RPM -- it only guards Spool-v2 decoder
     PIDs (logger.py:212). So clearing our SupportedPidSet is a NO-OP fix.
  5. The escalation swallows the null at core.py:1245 + latches _engineOnEscalated;
     US-221 recovery can't help (clears ECU-silent only on a SUCCESSFUL read).
     => RPM masked the whole connection -> drive_start never fires.
- Also structural: one probe only reaches STARTING; drive_start needs sustained RPM
  from the regular loop, which is masked identically.

### Why blocked (not fixed):
- The correct un-mask fix depends on python-obd internals + 2G K-line behavior NOT
  verifiable off the dev box (does a re-probe re-interrogate the ECU? is force=True
  clean on this ELM327? is the live backend real python-obd or a facade?). A guessed
  fix risks another mocked-green/IRL-miss regression -- exactly what verify-first
  exists to catch (the existing escalation tests MOCK queryAndLogParameter and never
  exercise the real mask, so they are green while the live path misses).
- Filed BL-016 with the live-Pi repro (cold-boot key-off -> engine-on), journalctl
  grep tokens, and 3 fix options (A refresh supported_commands / B force RPM /
  C alternator-active as first-class drive_start) for CIO bench-confirm + Atlas ruling.

### Learnings for future iterations:
- **Pattern discovered**: on a verify-first "residual gap" story, trace the FULL

  cache (force=False null-on-unsupported), NOT our _assertPidSupported gate. RPM
  bypasses _assertPidSupported entirely (it's in LEGACY_ECU_PARAMETERS, not
  PARAMETER_DECODERS) -- an easy wrong-fix trap.
- **Gotcha**: existing escalation tests mock the data logger's queryAndLogParameter,
