### Learnings for future iterations:
- **Pattern discovered**: the FakeRunner "first matching needle wins" dispatch lets
  you register ONE comprehensive per-table handler keyed on the table name and
  branch inside it on the SQL verb (TABLES / KEY_COLUMN_USAGE / ADD CONSTRAINT /
  LEFT JOIN) — cleaner than many narrow needles when a substep issues a mixed
  sequence of probes + DDL against a single table. Use a mutable `state` dict to
  flip the drives-referencing probe from absent->present after the ADD, so the
  post-condition probe passes.
- **Gotcha**: a migration must branch on the **applied** schema (information_schema),
  never the ORM's declared FK — the deployed MariaDB drifted from `create_all`
  (drive_statistics had NO summary_id FK), which is the whole of BL-020 / A-10.
  Any "the FK the ORM assumes must exist" precondition is the drift bug in disguise.
- **Gotcha**: orphan guard belongs on EVERY ADD path (state-1 after the drop AND
  state-3), not just one — factor it into the shared ADD helper.
