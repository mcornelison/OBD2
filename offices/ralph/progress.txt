### Learnings for future iterations:
- **Pattern discovered**: when a story says "feed X with real data, not a guessed
  constant", the real deliverable is usually a PIPELINE (measure -> config -> consume),
  not just the measuring tool. A hard-coded constant with no injection point can't
  be "fed" -- config-drive it (default = the old value, so behavior is preserved).
- **Pattern discovered**: keep the analysis a PURE function (list[Sample] -> Result)
  and inject clock+sleep into the sampler -> a hardware/bench story becomes fully
  unit-testable on the Windows dev box (no I2C, no real sleeping).
- **Gotcha**: `%%` is only correct inside argparse help strings (argparse does
  %-formatting); in a plain print() it renders literally as `%%`. Use a single `%`.
- **Gotcha**: the default pytest addopts (coverage) suppresses the pass/fail
  summary line when running a file subset; add `-p no:cov -o addopts=` to see the
  real "N passed" line. (Full-suite coverage stays a PM gate -- TD-059.)
- **Rule 2 held**: did NOT invent the measured settle number -- 180.0 stays as the
  grounded provisional default; the rig run (BENCH-ONLY validation) supplies the real value.
