### Learnings for future iterations:
- **Pattern discovered**: honest-instrument guard = pure function taking an injected "time-since-power-up" + an injected hardware double; the CLI wires real `/proc/uptime` + real `UpsMonitor`, tests wire lambdas + a fake. Keeps the cold-start rule unit-testable with zero hardware and no monkeypatching of `/proc`.
- **Gotcha**: `UpsMonitor()` construction is import- and cold-start-safe on Windows -- `smbus2` is imported lazily inside `I2cClient.connect` (not at module load), and `getBatteryPercentage()` only touches I2C on read (which the guard catches as `UpsMonitorError` -> NULL). So a non-Pi run records NULL, never crashes.
- **Gotcha**: dead-reference cleanup must follow the whole chain -- the `batteryHealthRecorder` ghost was CONSTRUCTED in `lifecycle.py` and threaded through the factory, not just stored in `hardware_manager`. Removing only the final store would leave a `TypeError` at the call site. grep the symbol across `src/` before declaring it dead.
- **Design note**: system uptime is a *conservative* calibration proxy -- the MAX17048 keeps its ModelGauge calibration across a bare Pi reboot while the UPS holds battery, so a post-reboot drill could NULL a genuinely-calibrated gauge. That errs toward NULL (the safe, honest direction); flagged to Atlas in `completionNotes` if a gauge-power-persistent signal is wanted later.
