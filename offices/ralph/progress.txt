### What was implemented:
- `SampleBus` broker class in bus.py: `__init__` (subs list + threading.Lock + dormant _retained dict)
- `subscribe(topics, qos, name, maxQueue=DEFAULT_MAX_QUEUE) -> Subscription` -- builds + registers a Subscription under the lock, returns it usable
- `publish(sample, retain=False) -> None` -- snapshots the sub list under the lock, then non-blocking `_offer()`s the sample into every subscription whose patterns match the topic (synchronous fan-out; the bounded queue is the only async boundary -> producer NEVER blocks)

Task: STATE retained topics (last-value-cache) + integrity-gap markers
Outcome: SHIPPED passes:true. Activated the dormant retain path + added the honest-instrument gap marker in the existing src/pi/bus/bus.py, TDD red->green from the slice-1 plan Task 4 + Task 5.

### What was implemented:
- `SampleBus.publish(sample, retain=True)` now stores the sample as the `_retained[topic]` last-value-cache (STREAM publishes with retain=False are NOT stored); only the latest per topic is kept

### Learnings for future iterations:
- **Pattern discovered**: the retain replay in subscribe() snapshots the matching retained samples *under* the lock but calls `_offer()` *outside* it -- same lock-discipline as publish()'s fan-out (US-381), so a slow new subscriber can't hold the bus lock during its initial replay.
- **Gotcha**: the gap marker must skip the overflowing subscription (`sub.name != subName`) -- otherwise emitting the marker would re-offer into the already-full victim and (for a victim that also matches `event.integrity.gap`) could recurse. Markers go only to OTHER subscribers.
