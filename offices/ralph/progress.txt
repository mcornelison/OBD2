- **Pattern discovered**: a "self-heal from an authoritative source" bug is often a
  "we trusted the drifted host as the source" bug. deploy-pi.sh pulled the bind MAC
  FROM the Pi's own .env, so the deploy could only ever re-propagate whatever the
  Pi already had. Bind from the REPO SSOT ($OBD_BT_MAC / addresses.sh), never from
  the target's current state.
- **Gotcha (surgical rewrite)**: to correct ONE key in an env file without
  clobbering siblings, `sed` only that line (`s|^...OBD_BT_MAC...=.*|OBD_BT_MAC=X|`)
  and pass the rest through -- do NOT wholesale-rewrite the file (install-rfcomm-
  bind.sh force-writes OBD_BT_CHANNEL=1, which the surgical corrector deliberately
  avoids per acceptance #3).
- **Gotcha (bench)**: the Windows sandbox blocks inline `VAR=x cmd | grep` and
  brace-group constructs; exercise the standalone helper directly (its --dry-run
  IS what the deploy step invokes) and set fixture paths via a Write'd file +
  `$OBDLINK_ENV_FILE`. shellcheck is not on the bench -> PM/integration gate.
