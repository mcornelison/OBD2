## Symptom (CIO report)

After the V0.29.24 deploy + reboot on the **bench** (not the car):
1. Boot startup splash did not appear.
2. Shutdown reverse splash did not appear.
3. After interacting with the dashboard UI, it **froze**.

## Evidence (Pi @ 10.27.27.100, this boot)

- `eclipse-states-http`, `eclipse-dashboard`, `graphical.target` all active; `splash-boot` enabled but inactive.
- `splash-boot` chromium ran ~5 s (20:20:16 -> 20:20:21) then `Deactivated successfully` via its by-design JS `window.close()` at HEALTHY_YIELD -> a fast boot may flash the splash briefly rather than never render.
- **State-server route auth anomaly (strongest lead):** `GET /` = 200, `GET /shutdown.html` = 200, but `GET /boot` `/boot.html` `/dashboard` `/shutdown` = **401**. If the shutdown splash loads `/shutdown` (401) it never renders. Looks like a NEW gate on bare routes.
- **Prime suspect:** US-501 modified `states_http_server.py` `_injectHtml` (version-chip injection) this sprint; also check US-484-lineage SSOT-token gating on these routes.
- Freeze: dashboard chromium still process-alive; US-501/502 touched `carousel.js` + emitters -- a JS error or a 401 fetch could hang the render loop.

## Impact

- **Blocks `/sprint-validated` for V0.29.24** -- the sprint deployed but has an open display regression. Chain-merge to main stays held regardless.
- Does not affect server (healthy, 29 drives) or the OBD capture path.
