# US-367 — Backfill 2 ECU lineage rows (supersede placeholder; close MD346675 era + open MD326328 era) + join verification

## Goal
As a server-side analytics consumer wanting per-drive ECU attribution, I want the historical ECU lineage backfilled into `vehicle_info` as exactly **two real eras** — prior ECU (`MD346675`) active before the ~2026-05-22 swap + new modified-EPROM ECU (`MD326328`) active from the swap onward — **superseding the degenerate `PRE_TRACKING_UNKNOWN` bootstrap placeholder**, so any drive's `start_time_utc` resolves to the ECU active at that time (and the stuck June-5 `dtc_freeze_frame` sync orphan self-heals). **Per Atlas 2026-06-28 ruling: 2 rows (option a), NOT 3.**

## Atlas ruling (2026-06-28 — closes the freeze-gate)
Atlas reviewed the PRD against the live resolver (`sync.py:564-609`), `stamp_ecu_swap.py`, and `vehicle_info_coherence.py` and ruled **2 rows (option a) — supersede the placeholder**:
1. **The placeholder is a non-era, not history.** Zero-width window (`install==removal==2026-05-01 11:53:45`) + `PRE_TRACKING_UNKNOWN` sentinel = no real ECU period; resolves zero captures. Append-only protects *real* lineage; a failed bootstrap row is not lineage.
2. **3 rows is a resolver hazard.** The resolver raises on `>1` matching window (`sync.py:605`). If `MD346675`'s era starts at-or-before the placeholder instant (it must, to cover pre-swap history) it matches BOTH rows → overlap violation. Avoiding it would force an artificial micro-gap (worse). 2 rows = gapless single-active partition = exactly the invariant the resolver wants.
3. **Append-only NOT violated.** It governs steady-state swaps via `stamp_ecu_swap`; the one-shot backfill is a sanctioned bootstrap. Correcting a botched bootstrap is the backfill's job.

## Definition of Done (**at least 1 criterion required** so Ralph knows when complete)
- **Supersede the placeholder.** Remove/repurpose the degenerate `PRE_TRACKING_UNKNOWN` row (`id=1, install==removal==2026-05-01 11:53:45`) — it is a failed bootstrap, NOT lineage; do **not** retain it as a 3rd live row. Net post-backfill state = exactly **2** real ECU-era rows.
- **FK target = `ecu_id`.** The backfill calls `resolveOrCreateEcu` for BOTH ECUs (`MD346675` + `MD326328`), sets `vehicle_info.ecu_id`, and **derives** the TEXT `ecu_signature`/`cal_signature` snapshot columns from the resolved `ecu` rows so `findEcuCoherenceViolations()` returns empty. (Resolver + coherence key on `ecu_id`; TEXT signatures are derived snapshots.)
- **Gapless single-active partition:**
  - **Prior ECU (`MD346675`)**: install = start-of-tracking (earliest tracked capture / the existing bootstrap instant → gapless partition start, **NULL** per Atlas); removal = swap instant.
  - **New ECU (`MD326328`)**: install = swap instant; removal = NULL (currently active).
- **Swap instant is Spool's to derive** (last old-ECU drive-end / first new-ECU drive-start, ~2026-05-22) and is passed to the backfill as a **script param** — NOT hardcoded.
- **Spool sign-off** on signature naming convention recorded BEFORE backfill (per F-108 last bullet).
- **Placeholder provenance** is recorded in the backfill script log + commit message — NOT as a live lineage row.
- **Bless the one-shot bootstrap/backfill script** as the SOLE sanctioned exception to "`stamp_ecu_swap` is the only `vehicle_info` mutator," scoped to initial spine establishment (`stamp_ecu_swap` correctly refuses here — placeholder closed → `getActiveVehicleInfo()==None`).
- **Data sources documented in commit body**: prior-ECU start-of-tracking source (earliest `realtime_data.captured_at` or `Eclipse 1998 Projects.gsheet` — approximate but documented); swap instant precise per Spool derivation.
- **Join verification**: `drive_summary JOIN vehicle_info ON start_time_utc` within `[install, COALESCE(removal, NOW())]` partitions drives 1-24 → prior (`MD346675`) + drives 25+ → new (`MD326328`).
- **Coherence verification**: `findEcuCoherenceViolations()` returns empty post-backfill; the resolver raises for NO drive (no `>1`-window overlap).

## Conditional outcomes
- if Spool has NOT signed off on the signature naming convention OR has NOT derived the swap instant, then BLOCK the backfill + route an A2AL note to Spool.
- if join verification shows any drive 1-24 partitioning to the new ECU (or any drive 25+ to the prior ECU), then the boundaries are wrong; revise + re-backfill.
- if the resolver raises a `>1`-window overlap for any drive post-backfill, the partition is not gapless-single-active — fix the install/removal boundaries (do NOT introduce an artificial micro-gap).
